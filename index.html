IPFS (Pinata) key - needed to issue certificates (not needed to verify). Get a free JWT at pinata.cloud - API Keys - New Key (Admin access is fine for a demo). Stored only in this browser's local storage, never sent anywhere except Pinata's API.
Never paste this key into the HTML file itself, and never commit a key to a public repository. If a key ever ends up in a repo or gets shared, revoke it from the Pinata dashboard and generate a new one - treat it exactly like a password.
These fields are assembled into one canonical record, hashed with keccak256 in your browser, and pinned to IPFS. Change one character later - anywhere - and the hash, and the verification, will no longer match. Nothing sensitive (address, phone, ID number) belongs in these fields - this record is publicly readable by anyone who has the certificate ID.

Submitting a request does not grant issuing rights by itself. The platform admin must separately confirm off-chain that this wallet really belongs to the institution it claims to be (an official email, letter, or call), then approve it from the Admin tab. This is what stops anyone from registering as a particular entity and self-issuing certificates that would otherwise render as verified. One wallet can only be associated with one issuer identity.
Only the wallet that deployed the contract can call approveIssuer or rejectIssuer - anyone else's transaction will revert. Before approving, verify off-chain that this address genuinely belongs to the institution named in its request (check the IssuerRequested event log on scan.botchain.ai for the name they submitted).
